# OREE DAM Monitor

Сервіс, який сам стежить за результатами торгів ринку «на добу наперед» (РДН) на ОРЕЕ.
Щогодини він завантажує офіційні дані, зберігає ціни й обсяги по кожній годині доби, показує їх
на графіку і в таблиці та надсилає повідомлення в Telegram, щойно з'являються результати на нову
добу або ОРЕЕ перераховує вже опубліковані.

Сервіс внутрішній і розрахований на одну людину чи невелику команду. Автентифікації немає, тож
він доступний лише з машини, на якій запущений.

## Що вміє

- **Збирає дані сам.** Раз на годину (інтервал налаштовується) завантажує офіційний CSV ОРЕЕ.
  Перший збір відбувається одразу після запуску, історію з 01.07.2019 можна довантажити однією
  командою.
- **Помічає лише справжні зміни.** Порівнює кожну добу з тим, що вже збережено, тож повторний збір
  тих самих даних нічого не змінює й нікого не турбує. Перерахунок ОРЕЕ вже опублікованої доби
  теж помічає.
- **Показує дані.** Графік цін і обсягів, таблиця, фільтр дат, погодинний або подобовий режим.
  Уся історія подобово відкривається менш ніж за секунду.
- **Надсилає сповіщення в Telegram.** Одне повідомлення на кожне реальне оновлення: дата,
  мінімальна, максимальна і середньозважена ціна за кожну змінену добу. Перераховані доби
  позначено окремо.
- **Керується з браузера.**
  - Вкладка «Дані»: стан останнього збору, помилки і кнопка «Оновити зараз».
  - Вкладка «Налаштування»: розклад збору, вимикач сповіщень, отримувачі в Telegram, тестове
    повідомлення і пошук чатів, які писали боту.

## Швидкий старт

Потрібні лише **Docker** (з Compose) і **make**.

```sh
make up
```

Відкрийте http://127.0.0.1:8080. Під час першого запуску `make up` створює `.env` з `.env.example`,
застосовує міграції бази і одразу робить перший збір даних з ОРЕЕ.

Графік спершу покаже лише поточний квартал. Щоб завантажити всю історію з 01.07.2019
(кілька хвилин):

```sh
make backfill
```

## Команди

| Команда | Що робить |
|---|---|
| `make up` | Зібрати й запустити сервіс, дочекатися готовності |
| `make down` | Зупинити сервіс; дані бази зберігаються |
| `make logs` | Журнали всіх сервісів у реальному часі |
| `make ps` | Стан сервісів |
| `make backfill` | Завантажити історію РДН з 01.07.2019 |
| `make clean` | Видалити контейнери, **базу даних** і зібрані образи (з підтвердженням; `.env` лишається) |

Без підтвердження: `make clean FORCE=1`.

## Сповіщення в Telegram (необов'язково)

1. Створіть бота в [@BotFather](https://t.me/BotFather) і впишіть токен у `.env`:
   `TELEGRAM_BOT_TOKEN=...`
2. Перезапустіть: `make down && make up`.
3. Напишіть боту `/start`, відкрийте вкладку «Налаштування» → «Знайти чати» → «Додати».
   Кнопка «Надіслати тест» перевіряє доставку.

Бот нічого не відповідає: він лише надсилає сповіщення. Пошук чатів бачить тих, хто писав боту за
останні 24 години. Для каналу бота треба додати адміністратором.

## Як це працює

```
ОРЕЕ (CSV за квартал) ──► збір ──► порівняння хешів діб ──► Postgres ──► веб-інтерфейс
                            ▲                                   │
                     планувальник                                └──► Telegram (лише якщо щось змінилось)
```

- **Звідки дані.** ОРЕЕ публікує результати на добу D у день D−1, приблизно о 12:30–13:00 за
  Києвом, одним CSV-файлом на квартал. Тому кожен збір бере квартал сьогоднішньої дати, а на межі
  кварталу — ще й наступний.
- **Результат кожного запуску** записується в журнал з одним зі статусів:
  - `success`: дані змінились;
  - `no_changes`: нових даних немає;
  - `no_data`: ОРЕЕ ще нічого не опублікував;
  - `error`: збій;
  - `skipped_locked`: інший збір уже йде.

  Два записи в базу одночасно неможливі.
- **Складова.** Три контейнери:
  - Postgres;
  - backend (Python, FastAPI, планувальник усередині);
  - веб-інтерфейс (React за nginx, який проксує `/api` на backend).

## Доступ і безпека

Сервіс не має автентифікації, тому доступний **лише з цієї машини**: усі порти опубліковано на
`127.0.0.1` (UI — 8080, API — 8000, Postgres — 5432). Не змінюйте це, щоб відкрити сервіс у мережу:
для цього спершу потрібні автентифікація і HTTPS (див. «Борги» в `docs/roadmap.md`).

Токен бота зберігається лише в `.env` і ніколи не показується в інтерфейсі.

Якщо порт уже зайнятий, змініть ліву частину відповідного `127.0.0.1:<порт>:...` у
`docker-compose.yml`.

## Розробка

База для розробки — той самий сервіс Postgres: `docker compose up -d postgres`. Далі:
- API: `cd backend && uv run python -m app.api`;
- UI: `cd frontend && npm run dev`;
- перевірка всього: `make check` (самоперевірка хуків, тести backend і frontend, lint, build).
  Потрібні запущений Docker, `uv` і `npm ci` у `frontend/`. Частинами: `make check-hooks`,
  `make check-backend`, `make check-frontend`.

Контейнерний стек і dev-запуск використовують **одну й ту саму базу** (том `postgres_data`), тож
`make clean` видалить і дані, з якими ви працювали локально.

| Де | Що |
|---|---|
| `backend/` | API, збір, планувальник, сповіщення, міграції, тести |
| `frontend/` | Веб-інтерфейс |
| `docs/brief.md` | Опис продукту і формату даних ОРЕЕ |
| `docs/roadmap.md` | У якому порядку будувався сервіс, що зроблено і які борги лишились |
| `openspec/specs/` | Специфікації: що система мусить робити, зі сценаріями |
| `AGENTS.md` | Правила для AI-агентів, які працюють з кодом |

Кожна зміна проходила шлях «пропозиція → специфікація → дизайн → задачі → реалізація» через
[OpenSpec](https://github.com/Fission-AI/OpenSpec); історія змін — в `openspec/changes/archive/`.
