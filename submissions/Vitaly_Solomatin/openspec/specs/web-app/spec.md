# web-app Specification

## Purpose

Вебзастосунок сервісу моніторингу РДН. Він збирається і запускається як окремий фронтенд, звертається
до API з того самого origin, проходить автентифікацію засобами браузера і показує користувачу
стан з'єднання з backend.

## Requirements

### Requirement: Доступ до API з того самого origin

Застосунок SHALL звертатися до API через шлях із префіксом `/api` на тому самому origin, з
якого його завантажено. У режимі розробки сервер розробки MUST перенаправляти запити `/api/*`
на backend без префікса `/api`. Адреса backend MUST налаштовуватися без зміни коду. Застосунок
MUST NOT вимагати від backend підтримки CORS.

#### Scenario: Перенаправлення запиту до API

- **GIVEN** сервер розробки фронтенду запущено, і backend доступний
- **WHEN** застосунок запитує `/api/health`
- **THEN** запит отримує backend як `/health`
- **AND** застосунок отримує відповідь backend

#### Scenario: Інша адреса backend

- **GIVEN** адресу backend задано змінною оточення сервера розробки
- **WHEN** застосунок запитує `/api/health`
- **THEN** запит надходить на задану адресу

### Requirement: Автентифікація засобами браузера

Застосунок MUST NOT містити форми входу чи зберігати облікові дані. Облікові дані SHALL
запитуватися системним вікном браузера у відповідь на відповідь backend 401 з викликом Basic,
і браузер SHALL надсилати їх із наступними запитами до того самого origin. Коли автентифікація
не пройдена, застосунок MUST показувати окремий стан «потрібна автентифікація», який не
плутається з недоступністю backend.

#### Scenario: Перший захищений запит

- **GIVEN** користувач відкрив застосунок і ще не вводив облікових даних
- **WHEN** застосунок запитує стан системи
- **THEN** браузер показує системне вікно автентифікації
- **AND** після введення правильних облікових даних застосунок показує стан системи

#### Scenario: Автентифікацію скасовано або не пройдено

- **GIVEN** backend відповідає на запит стану системи кодом 401
- **WHEN** застосунок обробляє відповідь
- **THEN** панель з'єднання показує стан «потрібна автентифікація»
- **AND** не показує стан «backend недоступний»

### Requirement: Стан з'єднання з API

Застосунок SHALL при завантаженні перевіряти живість backend і читати стан системи, а потім
показувати панель з'єднання в одному з чотирьох станів: завантаження; з'єднання в порядку, з
часом останньої перевірки й останнього оновлення даних; потрібна автентифікація; backend
недоступний. Часи MUST відображатися за часовим поясом Europe/Kyiv. Відсутність запусків у
журналі MUST відображатися як «ще не було», а не як помилка.

#### Scenario: З'єднання в порядку

- **GIVEN** backend доступний, автентифікацію пройдено, і в журналі є запуски
- **WHEN** застосунок завантажився
- **THEN** панель показує, що з'єднання в порядку
- **AND** показує час останньої перевірки й останнього оновлення даних за Europe/Kyiv

#### Scenario: Час за київським часом

- **GIVEN** останній запуск почався о `2026-09-28T09:00:00Z`
- **WHEN** панель показує час останньої перевірки
- **THEN** показаний час дорівнює 12:00 28.09.2026

#### Scenario: Журнал порожній

- **GIVEN** backend доступний, автентифікацію пройдено, і запусків ще не було
- **WHEN** застосунок завантажився
- **THEN** панель показує, що з'єднання в порядку
- **AND** на місці часу перевірки й оновлення показує «ще не було»

#### Scenario: Backend недоступний

- **GIVEN** backend не відповідає або відповідає помилкою сервера
- **WHEN** застосунок завантажився
- **THEN** панель показує стан «backend недоступний»

#### Scenario: Неочікувана відповідь

- **GIVEN** backend відповідає кодом 200, але тіло не відповідає контракту стану системи
- **WHEN** застосунок обробляє відповідь
- **THEN** панель показує стан помилки з'єднання, а не порожні значення

### Requirement: Збирання і перевірки якості

Фронтенд SHALL збиратися у статичні файли однією командою, а типи й код MUST проходити
перевірку типів, лінтер і тести без помилок.

#### Scenario: Продакшн-збирання

- **GIVEN** встановлено залежності фронтенду
- **WHEN** виконується команда збирання
- **THEN** збирання завершується успішно і створює статичні файли

#### Scenario: Перевірки якості

- **GIVEN** встановлено залежності фронтенду
- **WHEN** виконуються перевірка типів, лінтер і тести
- **THEN** усі три завершуються без помилок
