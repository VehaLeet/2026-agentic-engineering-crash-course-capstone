# local-deployment Specification

## Purpose

Запуск усього сервісу моніторингу РДН на одній машині з однієї команди, без встановлення Python і
Node: база даних, API з планувальником і веб-інтерфейс у контейнерах, доступні лише з localhost.

## Requirements

### Requirement: Запуск однією командою

`make up` SHALL зібрати образи й запустити базу даних, API і веб-інтерфейс, дочекатися, доки API
відповідає на перевірку живості, і показати адресу веб-інтерфейсу `http://127.0.0.1:8080`. Для
цього на машині MUST бути потрібні лише Docker і make. Якщо файлу `.env` немає, `make up` SHALL
створити його з `.env.example` і повідомити про це. Повторний `make up` на вже запущеному стеку
MUST NOT втрачати дані.

#### Scenario: Перший запуск на чистій машині

- **GIVEN** встановлено лише Docker і make, файлу `.env` немає
- **WHEN** виконується `make up`
- **THEN** створено `.env` з `.env.example`
- **AND** після завершення команди `http://127.0.0.1:8080` відкриває веб-інтерфейс
- **AND** вкладка «Налаштування» показує розклад з інтервалом 60 хвилин

#### Scenario: API не піднявся

- **GIVEN** API не відповідає на перевірку живості протягом відведеного часу
- **WHEN** виконується `make up`
- **THEN** команда завершується ненульовим кодом і підказує `make logs`

### Requirement: Автоматичні міграції

Перед стартом API контейнер backend SHALL застосувати всі міграції бази даних. Якщо міграції не
вдалися, API MUST NOT стартувати, а причина MUST бути видимою в `make logs`.

#### Scenario: Порожня база

- **GIVEN** том бази даних порожній
- **WHEN** стартує стек
- **THEN** схема бази відповідає останній міграції
- **AND** налаштування мають типові значення

### Requirement: Доступ лише з localhost

Кожен порт, який стек публікує на хості, MUST бути прив'язаний до `127.0.0.1`. Веб-інтерфейс SHALL
бути доступним на порту 8080, API — на порту 8000, база даних — на порту 5432, усі лише з loopback.
Веб-інтерфейс SHALL звертатися до API через той самий origin за префіксом `/api`.

#### Scenario: Порти лише на loopback

- **GIVEN** стек запущено
- **WHEN** перевіряється конфігурація опублікованих портів
- **THEN** кожен опублікований порт прив'язаний до `127.0.0.1`

#### Scenario: Запит з іншої машини

- **GIVEN** стек запущено на машині з адресою `192.168.1.10` у локальній мережі
- **WHEN** інша машина звертається до `http://192.168.1.10:8080`
- **THEN** з'єднання не встановлюється

#### Scenario: UI звертається до API

- **GIVEN** стек запущено
- **WHEN** браузер запитує `http://127.0.0.1:8080/api/health`
- **THEN** відповідь має код 200 від API

### Requirement: Зупинка без втрати даних

`make down` SHALL зупинити й прибрати контейнери, але MUST зберегти дані бази. Наступний
`make up` MUST показати ті самі дані, налаштування й отримувачів.

#### Scenario: Дані переживають зупинку

- **GIVEN** у базі є дані РДН і отримувач Telegram
- **WHEN** виконуються `make down`, а потім `make up`
- **THEN** дані РДН і отримувач на місці

### Requirement: Повне очищення

`make clean` SHALL прибрати контейнери, том бази даних і зібрані образи стеку. Оскільки дані
втрачаються безповоротно, команда MUST попросити підтвердження і MUST NOT нічого видаляти без
нього. Підтвердження SHALL можна передати заздалегідь (`make clean FORCE=1`) для
неінтерактивного використання. Файл `.env` MUST NOT видалятися.

#### Scenario: Підтверджене очищення

- **GIVEN** стек запущено і в базі є дані
- **WHEN** виконується `make clean` і користувач підтверджує
- **THEN** контейнерів, тому бази й образів стеку немає
- **AND** `.env` лишився
- **AND** наступний `make up` стартує з порожньою базою

#### Scenario: Скасоване очищення

- **GIVEN** стек запущено
- **WHEN** виконується `make clean` і користувач не підтверджує
- **THEN** нічого не видалено

### Requirement: Допоміжні команди

Makefile SHALL мати `make help` (типова ціль) з переліком команд і їхнім описом, `make logs`
(журнали всіх сервісів у реальному часі), `make ps` (стан сервісів) і `make backfill` (завантаження
історії РДН з 01.07.2019 у запущеному стеку).

#### Scenario: Довідка

- **GIVEN** репозиторій склоновано
- **WHEN** виконується `make` без аргументів
- **THEN** показано перелік команд з описом

#### Scenario: Бекфіл історії

- **GIVEN** стек запущено з порожньою базою
- **WHEN** виконується `make backfill`
- **THEN** у базі з'являється історія РДН з 01.07.2019
- **AND** графік у веб-інтерфейсі показує її

#### Scenario: Бекфіл без запущеного стеку

- **GIVEN** стек не запущено
- **WHEN** виконується `make backfill`
- **THEN** команда завершується ненульовим кодом і підказує `make up`
