## Why

Зараз UI показує, коли система востаннє перевіряла ОРЕЕ і коли дані змінилися, але не дає
нічого з цим зробити. Щоб підтягнути щойно опубліковані результати, треба йти в термінал. Бриф
вимагає кнопку «Оновити зараз» і панель статусу з останніми помилками, а API для цього вже є
(зріз 5): `POST /collect` відповідає `202` з `run_id`, а результат читається з `GET /runs/{id}`.
Цей зріз замикає цикл «запустити збір → побачити результат → побачити нові дані» в браузері.

## What Changes

- **Кнопка «Оновити зараз»** на панелі статусу. Вона запускає збір через `POST /collect`,
  опитує `GET /runs/{id}` до фінального статусу й показує результат. Поки запуск триває, кнопка
  недоступна.
- **Результат запуску людською мовою** для кожного з п'яти статусів:
  - `success` — «Дані оновлено» з переліком змінених діб постачання;
  - `no_changes` — «Нових даних немає»;
  - `no_data` — «ОРЕЕ ще не опублікував дані»;
  - `skipped_locked` — «Збір уже виконується»;
  - `error` — текст помилки.
- **Після `success` дані оновлюються самі**: панель статусу й графік із таблицею
  перезавантажуються для поточного діапазону без перезавантаження сторінки.
- **Перелік останніх помилок збору** з `GET /status` (до 5, найновіші першими): час за Києвом і
  текст помилки. Якщо помилок немає, це видно явно.
- **Межа очікування**: якщо запуск не завершився за 2 хвилини (найгірший випадок ретраїв ОРЕЕ —
  близько 90 с), UI перестає опитувати, пише «Збір триває довше, ніж очікувалось» і знову робить
  кнопку доступною. Сам запуск від цього не скасовується.
- **Незавершений останній запуск** (`status: null`, наприклад після загибелі процесу) показується
  як «не завершено», а не як помилка чи успіх.

### Що НЕ входить у цю зміну

- Налаштування (отримувачі Telegram, частота, вимикач) — зріз 11b (`add-web-settings`).
- Скасування запущеного збору, повний журнал запусків зі сторінками, фільтри журналу.
- Автоматичне періодичне оновлення панелі (polling стану без дії користувача) — з'явиться разом із
  планувальником (зріз 8).
- Будь-які зміни backend і API.

## Capabilities

### New Capabilities

- `web-status`: керування збором і перегляд його стану з браузера — ручний запуск збору з
  доведенням до фінального статусу, людський опис результату, автоматичне оновлення даних після
  успіху, перелік останніх помилок збору.

### Modified Capabilities

Немає. Вимога `web-app` «Стан з'єднання з API» (завантаження / в порядку / backend недоступний,
час перевірки й оновлення) не змінюється: цей зріз додає поряд із нею окремі кнопку й перелік
помилок. `http-api` використовується як є.

## Impact

- **Frontend:** POST у клієнті API, типи `CollectAccepted`, сховище ручного запуску з опитуванням,
  компоненти «Оновити зараз» і перелік помилок, тести.
- **Backend, API, схема БД, залежності:** без змін.
- **Документація:** статус зрізу 11a в `docs/roadmap.md`.
