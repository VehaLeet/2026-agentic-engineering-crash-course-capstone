## 1. Діапазон кварталів

- [x] 1.1 Реалізувати тип кварталу (рік, номер) і його перебір із переходом через рік;
      перевірка: тест стверджує, що наступний після 2026Q4 — це 2027Q1, а перебір
      2025Q1..2026Q2 дає рівно 6 кварталів у хронологічному порядку.
- [x] 1.2 Розбір аргументів `--from` / `--to` у форматі `YYYYQN`; перевірка: тест на `2025Q1`
      дає (2025, 1), а на `2025Q5` і `20251` — помилку розбору.
- [x] 1.3 Дефолтні межі: від 2019Q3 до кварталу поточної дати включно; перевірка: тест із
      підставною поточною датою 15.08.2026 стверджує верхню межу 2026Q3.
- [x] 1.4 Відхиляти перевернутий діапазон до будь-якого мережевого запиту; перевірка: тест
      на `--from 2025Q4 --to 2025Q1` очікує помилку і стверджує **нуль** звернень до джерела.
- [x] 1.5 Діапазон з одного кварталу; перевірка: тест на однакових межах стверджує рівно
      одне завантаження.

## 2. Основний цикл бекфілу

- [x] 2.1 Реалізувати послідовну обробку діапазону через `dam-source` і `dam-storage`;
      перевірка: тест на підставному джерелі з двома кварталами стверджує, що записи обох
      є у сховищі, а порядок обробки хронологічний.
- [x] 2.2 Фіксувати кожен квартал окремою транзакцією; перевірка: тест, де збереження
      третього кварталу кидає виняток, стверджує цілість перших двох і відсутність
      частково збереженого третього.
- [x] 2.3 Зберігати сирий знімок і хеші діб для кожного непорожнього кварталу; перевірка:
      тест на трьох кварталах стверджує три знімки і наявність хешу для кожної збереженої доби.
- [x] 2.4 Порожній квартал не спричиняє ні помилки, ні знімка; перевірка: тест на діапазоні,
      що включає 2019Q2, стверджує відсутність винятку і відсутність знімка для нього.

## 3. Ідемпотентність

- [x] 3.1 Перевірка повторного прогону: тест виконує бекфіл двічі на тому самому діапазоні
      і стверджує незмінну кількість рядків та незмінні значення.
- [x] 3.2 Перевірка перекриття діапазонів: тест виконує 2025Q1–Q2, потім 2025Q2–Q3, і
      стверджує відсутність дублікатів за Q2 та наявність даних Q3.
- [x] 3.3 Перевірка оновлення при зміні в джерелі: тест виконує бекфіл, змінює значення
      у підставному джерелі, виконує повторно і стверджує оновлене значення при незмінній
      кількості рядків.
- [x] 3.4 Перевірка, що знімки не дублюються: тест виконує бекфіл двічі і стверджує незмінну
      кількість сирих знімків.

## 4. Відновлюваність і стійкість до збоїв

- [x] 4.1 Ізолювати збій окремого кварталу так, щоб цикл продовжувався; перевірка: тест на
      трьох кварталах, де другий кидає помилку завантаження, стверджує наявність даних
      першого і третього.
- [x] 4.2 Повертати ненульовий код виходу при хоч одному невдалому кварталі; перевірка: тест
      стверджує код виходу 1 для прогону з одним збоєм і 0 для повністю успішного.
- [x] 4.3 Продовження після перерви: тест перериває бекфіл на третьому з чотирьох кварталів
      підставним винятком, запускає повторно і стверджує наявність даних усіх чотирьох.
- [x] 4.4 Пошкоджені дані одного кварталу не зберігаються частково; перевірка: тест на
      кварталі з нерозбірним рядком стверджує нуль рядків за цей квартал і його позначення
      як невдалого.
- [x] 4.5 Не додавати власних ретраїв поверх `dam-source`; перевірка: тест стверджує рівно
      одне звернення бекфілу на квартал при постійному збої.

## 5. Обмеження темпу

- [x] 5.1 Пауза між завантаженнями, налаштовувана аргументом `--delay`; перевірка: тест із

- [x] 5.2 `--delay 0` вимикає паузи; перевірка: тест стверджує нуль викликів таймера.

## 6. Вивід і підсумок

- [x] 6.1 Друкувати рядок на кожен квартал із кількістю збережених діб і рядків; перевірка:
      тест захоплює вивід і стверджує наявність рядка на кожен квартал із коректними числами.
- [x] 6.2 Позначати порожній квартал як порожній, а не як невдалий; перевірка: тест стверджує,
      що вивід для порожнього кварталу не потрапляє до переліку невдалих.
- [x] 6.3 Друкувати підсумок із кількістю успішних, порожніх і невдалих кварталів та переліком
      невдалих; перевірка: тест на прогоні 2 успішних / 1 порожній / 1 невдалий стверджує всі
      чотири числа і назву невдалого кварталу у виводі.

## 7. Перевірка на реальних даних

- [x] 7.1 Прогнати бекфіл проти живого ОРЕЕ за повний дефолтний діапазон; перевірка: команда
      завершується кодом 0, у БД ~63 тис. рядків і ~29 знімків, підсумок без невдалих кварталів.
- [x] 7.2 Перевірити критерій MVP на реальному обсязі: виміряти читання діапазону за повний
      рік і за весь наявний період; перевірка: обидва запити виконуються **швидше за 1 с**,
      результат зафіксовано у журналі. Якщо ні — зафіксувати як вхід для окремої зміни індексів
      у `dam-storage`, не правити схему в цьому зрізі.
- [x] 7.3 Перевірити дні переходу часу на всій історії: запит стверджує, що кожна доба має
      24 періоди, окрім діб переходу, які мають 23 або 25, і що таких діб рівно по одній
      на рік кожного типу.
- [x] 7.4 Перевірити ідемпотентність на реальних даних: повторний прогін повного діапазону
      не змінює кількості рядків і знімків.
- [x] 7.5 Прогнати `pytest` і `openspec validate add-history-backfill --strict`; перевірка:
      обидві команди успішні, і кожен сценарій зі `specs/history-backfill/spec.md` має
      відповідний тест.
