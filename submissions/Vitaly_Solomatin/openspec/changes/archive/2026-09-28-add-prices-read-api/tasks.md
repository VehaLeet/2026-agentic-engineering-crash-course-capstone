## 1. Подобове читання в репозиторії

- [x] 1.1 Описати `DailyPrices` і реалізувати `DamRepository.get_daily(date_from, date_to)` одним
      SQL-запитом із `GROUP BY delivery_date`; перевірка: тест на двох синтетичних добах
      стверджує по одному рядку на добу, упорядкованих за датою.
- [x] 1.2 Перевірити агрегати на синтетичній добі з відомими числами; перевірка: тест стверджує
      точні `price_min`, `price_max`, `price_avg` (проста середня, 2 знаки), `price_weighted`
      (зважена за обсягом продажу, 2 знаки) і суми всіх чотирьох обсягів як `Decimal`.
- [x] 1.3 Нульовий сумарний обсяг продажу; перевірка: тест стверджує, що `price_weighted is None`,
      а решта агрегатів присутня.
- [x] 1.4 Кількість періодів у дні переходу часу; перевірка: тест на фікстурах 2025 Q1 і
      2025 Q4 стверджує `periods == 23` для 30.03.2025 і `25` для 26.10.2025.
- [x] 1.5 Порожній діапазон; перевірка: тест стверджує порожній список без помилки.

## 2. Маршрут `GET /prices`

- [x] 2.1 Додати маршрут на захищений роутер із параметрами `date_from`, `date_to` (обов'язкові
      дати) і `resolution` (`hour` | `day`, типово `hour`); перевірка: тест «кожен маршрут, крім
      `/health`, захищений» оновлено очікуваним набором із `/prices`, і для `/prices` він
      стверджує 401 без кредів.
- [x] 2.2 Погодинна відповідь у колонковому форматі за контрактом із `design.md`; перевірка:
      тест на добі 01.07.2026 стверджує 24 елементи в кожному масиві, `period == [1..24]`,
      наявність усіх п'яти величин і `resolution: "hour"`.
- [x] 2.3 Роздільність за замовчуванням; перевірка: запит без `resolution` повертає
      `resolution: "hour"`.
- [x] 2.4 Доба з 25 періодами погодинно; перевірка: тест на 26.10.2025 стверджує
      `period == [1..25]`.
- [x] 2.5 Подобова відповідь за контрактом; перевірка: тест стверджує набір полів, однакову
      довжину масивів, `resolution: "day"` і JSON-`null` у `price_weighted` для доби з нульовим
      обсягом.
- [x] 2.6 Включні межі й порожній діапазон; перевірка: тест на даних за 1–10 липня запитує
      3–5 і стверджує рівно ці три доби; діапазон без даних повертає 200 і порожні масиви.

## 3. Валідація параметрів

- [x] 3.1 Відсутня межа і некоректна дата; перевірка: тести на запит без `date_to` і з
      `date_from=2026-13-01` стверджують 422.
- [x] 3.2 Перевернутий діапазон; перевірка: тест стверджує 422 і відсутність звернення до
      репозиторію.
- [x] 3.3 Невідома роздільність; перевірка: тест на `resolution=week` стверджує 422.
- [x] 3.4 Ліміт погодинного діапазону; перевірка: тести стверджують 200 для 2024-01-01..2024-12-31
      (366 діб) і 422 для 2024-01-01..2025-01-01 (367 діб) з повідомленням, що містить
      `resolution=day`.
- [x] 3.5 Подобова роздільність без ліміту; перевірка: тест на 2019-01-01..2026-12-31 з
      `resolution=day` стверджує 200.
