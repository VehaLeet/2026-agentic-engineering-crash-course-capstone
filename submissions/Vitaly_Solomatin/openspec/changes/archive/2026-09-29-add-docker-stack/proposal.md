## Why

Щоб запустити сервіс, зараз треба окремо підняти Postgres у Docker, встановити uv і Node,
застосувати міграції, запустити API і dev-сервер Vite. Для людини, яка хоче лише спробувати
сервіс, це п'ять кроків і два інструменти, яких у неї може не бути. «Контейнеризація backend»
записана боргом у дорожній карті саме з цієї причини.

## What Changes

- **Увесь стек у docker-compose:** `postgres` (як зараз), `backend` (API з планувальником) і
  `web` (зібраний фронтенд за nginx, який проксує `/api` на backend). Для запуску потрібні лише
  Docker і make.
- **Міграції автоматично:** backend застосовує `alembic upgrade head` перед стартом API.
- **Межа localhost зберігається:** усі порти публікуються лише на `127.0.0.1`
  (UI — `http://127.0.0.1:8080`). Щоб API в контейнері міг слухати `0.0.0.0` усередині мережі
  compose, запускач отримує явний режим контейнера (`API_IN_CONTAINER=1`), який діє лише
  всередині контейнера. Поза контейнером запускач, як і раніше, відмовляє для не-loopback адрес.
- **Makefile з однією командою на дію:** `make up` (зібрати й запустити, дочекатися готовності,
  показати адресу), `make down` (зупинити, дані лишаються), `make logs`, `make ps`,
  `make backfill` (завантажити історію з 2019 року), `make clean` (усе прибрати разом із даними,
  з підтвердженням) і `make help`. Якщо `.env` немає, `make up` створює його з `.env.example`.
- **README з швидким стартом** для тих, хто тестує сервіс.

### Що НЕ входить у цю зміну

- Продакшн-розгортання: TLS, автентифікація, доступ з мережі (борг «Автентифікація і TLS»
  лишається).
- Запуск тестів у контейнерах: тести, як і раніше, запускаються на хості через uv і npm.
- Hot reload у контейнерах: для розробки лишається `uv run python -m app.api` і `npm run dev`.
- Публікація образів у реєстр і CI.
- Зміни схеми БД чи API.

## Capabilities

### New Capabilities

- `local-deployment`: запуск усього сервісу на одній машині з однієї команди — склад сервісів,
  публікація портів лише на loopback, автоматичні міграції, збереження даних між зупинками,
  повне очищення і команди Makefile.

### Modified Capabilities

- `http-api`: «Доступ лише з localhost» — з'являється явний режим контейнера, у якому API може
  слухати `0.0.0.0` усередині контейнера; межу доступу тоді тримає публікація портів лише на
  `127.0.0.1`. Поза контейнером поведінка не змінюється.

## Impact

- **Нові файли:** `backend/Dockerfile`, `frontend/Dockerfile`, `frontend/nginx.conf`,
  `.dockerignore`-файли, `Makefile`, `README.md`.
- **Змінені файли:** `docker-compose.yml` (сервіси `backend` і `web`), `app/api/__main__.py`
  (режим контейнера), `.env.example` (документація змінних).
- **Залежності:** нових Python- чи npm-залежностей немає; базові образи `python:3.12-slim`,
  `node:24-alpine`, `nginx:alpine`, `uv` з офіційного образу.
- **Документація:** `docs/roadmap.md` — борг «Контейнеризація backend» закрито.
