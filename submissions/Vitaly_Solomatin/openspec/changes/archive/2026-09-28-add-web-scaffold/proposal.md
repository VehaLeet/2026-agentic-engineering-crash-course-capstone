## Why

Бекенд уже вміє головне: збирає дані, веде журнал і віддає ціни через автентифікований API.
Фронтенду при цьому немає зовсім, навіть каталогу `frontend/`, хоча бриф і конвенції проєкту
його передбачають. До графіка й таблиці (зріз 10b) треба окремо вирішити інфраструктуру: як
фронтенд збирається, як він потрапляє до API і як браузер проходить Basic Auth. Цей зріз закриває
саме ці питання, щоб наступні зміни займалися лише відображенням даних.

Щоб зріз був вертикальним, а не голим шаблоном, сторінка показує реальний стан з'єднання з API:
чи живий backend, чи пройдено автентифікацію і коли система востаннє перевіряла ОРЕЕ.

## What Changes

- Каталог `frontend/`: Vite + React + TypeScript + Zustand. Стек узято з брифу.
- **Той самий origin для фронтенду й API** через проксі Vite: запити на `/api/*` у розробці
  перенаправляються на backend (`http://localhost:8000` за замовчуванням, адресу можна
  змінити змінною оточення), префікс `/api` при цьому знімається. CORS не потрібен.
- **Basic Auth через системне вікно браузера.** Фронтенд не має жодного коду автентифікації:
  на перший захищений запит backend відповідає 401 з `WWW-Authenticate: Basic`, браузер показує
  вікно логіна і далі сам додає креди до запитів. Backend не змінюється.
- Тонкий типізований клієнт API: один модуль, типи відповідей `/health` і `/status` за
  контрактом `http-api`. Помилки розрізняються за видом: немає автентифікації (401), backend
  недоступний (мережа або 5xx), неочікувана відповідь.
- Стан з'єднання в сховищі Zustand, щоб сховище з'явилося в проєкті одразу з реальним
  використанням, а не «на майбутнє».
- Сторінка з заголовком сервісу і панеллю з'єднання, у якої чотири стани: завантаження, OK з
  часом останньої перевірки й останнього оновлення, «потрібна автентифікація», «backend
  недоступний». **Час показується за Europe/Kyiv**, як і опорна дата збору.
- Тести: Vitest + Testing Library (jsdom) на клієнт API, сховище і всі чотири стани панелі.
  Перевірка типів `tsc --noEmit` і ESLint із шаблону Vite.

### Що НЕ входить у цю зміну

- ECharts, графік, таблиця, фільтр дат, будь-який виклик `/prices` — це зріз 10b
  (`add-web-data-view`).
- Кнопка «Оновити зараз», перелік помилок, опитування `/runs/{id}` — це зріз 11a
  (`add-web-status`). Панель лише читає `/status` один раз при завантаженні.
- Власна форма входу, кнопка «Вийти», зберігання кредів у фронтенді.
- Будь-які зміни backend.
- Продакшн-віддача зібраного фронтенду, Dockerfile, сервіс `frontend` у compose, TLS. Це борг
  «контейнеризація й TLS» з `docs/roadmap.md`: розробка на `localhost` від нього не залежить.
- Маршрутизація між сторінками (router), UI-бібліотека компонентів, i18n. Інтерфейс
  українською, тексти прямо в компонентах.
- E2E-тести в браузері (Playwright). Системне вікно логіна перевіряється вручну.

## Capabilities

### New Capabilities

- `web-app`: вебзастосунок сервісу, тобто збирання й запуск фронтенду, доступ до API з того
  самого origin, проходження Basic Auth через браузер і відображення стану з'єднання з API з
  розрізненням автентифікації та недоступності backend.

### Modified Capabilities

Немає. Фронтенд — новий клієнт наявного `http-api`, і вимоги API від нього не змінюються.

## Impact

- **Новий код:** `frontend/` (конфігурація Vite з проксі, клієнт API, сховище, сторінка, тести).
- **Залежності:** `react`, `react-dom`, `zustand`; для розробки `vite`, `typescript`,
  `@vitejs/plugin-react`, `vitest`, `@testing-library/react`, `jsdom`, ESLint із шаблону.
  Потрібні Node.js ≥ 20 і npm (на машині розробника є Node 24).
- **Репозиторій:** `.gitignore` для `node_modules/` і `dist/`; `package-lock.json` комітиться.
- **Документація:** `frontend/README.md` з інструкцією запуску backend і frontend разом;
  статус зрізу 10a в `docs/roadmap.md`.
- **Backend:** без змін.
- **Розблоковує:** зріз 10b додає графік до готового застосунку з робочим клієнтом API та
  автентифікацією.
