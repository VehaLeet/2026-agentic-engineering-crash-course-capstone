## Context

Мотивація й межі — у `proposal.md`, вимоги — у `specs/web-data-view/spec.md` і
`specs/web-app/spec.md`.

Що вже є:

- `GET /prices?date_from&date_to&resolution=hour|day` віддає колонковий JSON (`prices-api`).
  Погодинно: `delivery_date`, `period`, `price`, чотири обсяги. Подобово: `price_min`,
  `price_max`, `price_avg` (BASE), `price_weighted` (може бути `null`), чотири суми обсягів,
  `periods`. Ліміт погодинного діапазону — 366 діб, інакше 422 з `detail`. Автентифікації немає.
- Frontend: `api/client.ts` з `request()`, класами `ApiUnavailable` і `ApiContractError`;
  Zustand-сховище `useConnection`; `formatKyiv(iso)`; проксі Vite `/api/*`. Тести Vitest у jsdom.
- Заміри зрізу 6: уся історія подобово — 46 мс і 2 648 точок; рік погодинно — 62 мс і
  8 760 точок. Це повний HTTP-цикл.
- Історія в БД починається з 01.07.2019.

## Goals / Non-Goals

**Goals:**

- Правильний час за Києвом для кожного періоду, включно з днями переходу, в браузері з будь-
  яким часовим поясом.
- «< 1 с» від вибору до графіка для будь-якого доступного в UI діапазону.
- Логіку (дати, перетворення часу, опцію графіка, форматування) перевіряють юніт-тести
  без canvas і без мережі.

**Non-Goals:**

- `dataZoom`, сортування таблиці, збереження стану в URL.
- Обгортки на кшталт `echarts-for-react`: власного хука на ~20 рядків достатньо.

## Decisions

### Період → час: опівніч за Києвом як момент, далі реальні години

```
start(date, p) = instant( 00:00 Europe/Kyiv на date ) + (p - 1) * 3600 s
```

Період — це порядкова година торгової доби, тож рахувати треба в **реальних годинах від
опівночі**, а не в годинах місцевого циферблата. Тоді обидва дні переходу обробляються без
жодних окремих гілок:

```
30.03.2025 (23 п.)  опівніч = 22:00Z попереднього дня
  p3 -> 00:00Z = 02:00 EET        p4 -> 01:00Z = 04:00 EEST   (03:00 не існує)
26.10.2025 (25 п.)  опівніч = 21:00Z попереднього дня
  p4 -> 00:00Z = 03:00 EEST       p5 -> 01:00Z = 03:00 EET    (03:00 двічі)
```

Момент опівночі за Києвом знаходиться без бібліотек: зсув пояса на цю дату береться з
`Intl.DateTimeFormat('en', {timeZone: 'Europe/Kyiv', timeZoneName: 'longOffset'})`, а якщо
потрібно, одна корекція повторює обчислення зі зсувом на знайденому моменті. Опівніч у Києві
ніколи не потрапляє на перехід (він о 03:00 або 04:00), тож однієї корекції завжди досить.

Альтернативи. `date-fns-tz` чи Luxon — зайва залежність для однієї функції. Наївне `new
Date(date + 'T00:00')` дає опівніч за поясом **браузера**, а не Києва.

Тести фіксують усі три приклади вище, і їх запускають з `TZ=UTC` та `TZ=America/New_York`,
щоб довести незалежність від пояса браузера.

### Вісь графіка — категорійна з готовими підписами, а не `time`

Вісь типу `time` в ECharts форматує підписи за поясом браузера. Замість неї вісь має тип
`category`, а підписи обчислюємо самі за Києвом:

- погодинно — `DD.MM HH:00`, на повторній годині з позначкою періоду: `26.10 03:00 (п.5)`;
- подобово — `DD.MM.YY`.

Підказка (tooltip) показує повну дату, період, час і значення.

Ціна категорійної осі в тому, що ECharts не «знає» проміжків часу між точками. Для наших даних
пропусків немає: дані публікуються суцільно добами, і кожна точка — наступний період чи доба.
Тож категорійна вісь нічого не спотворює.

### Графік: одна чиста функція опції + тонкий хук

```ts
buildChartOption(data: PricesHourly | PricesDaily, theme): EChartsOption   // чиста, тестується
useEChart(ref, option)   // init / setOption / resize / dispose; єдине місце, що торкається canvas
```

- Погодинно: `line` ціни на лівій осі (грн/МВт·год), `bar` обсягу продажу на правій (МВт·год).
- Подобово: `line` зваженої середньої (основна, товща), `line` мінімуму й максимуму (тонкі,
  пунктир), `bar` суми обсягу продажу. `price_weighted: null` передається в серію як `null`,
  і ECharts малює розрив, а не нуль.
- `sampling: 'lttb'` на лініях і `large: true` на стовпцях для рядів понад 1 000 точок.
  Проріджування стосується лише рендеру, таблиця показує всі дані.
- `animation: false` для рядів понад 1 000 точок, щоб анімація не з'їдала бюджет «< 1 с».
- Імпорт модульний: `echarts/core` + `LineChart`, `BarChart`, `GridComponent`,
  `TooltipComponent`, `LegendComponent`, `CanvasRenderer`, тобто без повного пакета.

В jsdom немає canvas, тому тести компонентів підміняють `useEChart`, а опцію перевіряють
через `buildChartOption`.

### Сховище даних: захист від застарілих відповідей

```ts
usePrices: { range, resolution, state, setRange, setResolution, load }
state: loading | { ok, data } | empty | unavailable | { invalid, message } | { error, message }
```

Кожен `load()` отримує зростаючий номер запиту. Відповідь застосовується, лише якщо її номер
збігається з останнім. Інакше повільна відповідь на старий діапазон перезаписала б новий.
Скасування через `AbortController` теж є, але лише як оптимізація. Коректність гарантує номер.

Перевірки до запиту, щоб не звертатися до API даремно:

- `date_from > date_to` → `invalid`, без запиту;
- `hour` і довжина > 366 діб → погодинний режим недоступний у перемикачі, без запиту. Пресети
  «Уся історія» і будь-який довгий діапазон самі перемикають на `day`.

422 від API все одно обробляється (`invalid` з `detail`) на випадок, якщо обмеження в UI і API
колись розійдуться.

### Діапазони

«Сьогодні» — це `kyiv_today`-аналог у frontend (дата за Europe/Kyiv). Кінець типового діапазону —
завтра, бо результати на завтра публікуються сьогодні близько 13:00. Якщо їх ще немає, остання
доба просто буде відсутня в даних, і це не помилка.

| Пресет | Від | До | Роздільність |
|---|---|---|---|
| 7 днів (типово) | завтра − 6 | завтра | hour |
| 30 днів | завтра − 29 | завтра | hour |
| Рік | завтра − 365 | завтра | hour (366 діб — у межах ліміту) |
| Уся історія | 2019-07-01 | завтра | day (примусово) |

### Таблиця

Звичайна HTML-таблиця з посторінковим переглядом по 100 рядків: «‹ Попередня», «Сторінка N з
M», «Наступна ›». Віртуалізація (react-window) була б ще однією залежністю, а сторінки
розв'язують ту саму задачу для 8 760 рядків і простіші для доступності. Зміна даних повертає
на першу сторінку.

### Форматування чисел

`Intl.NumberFormat('uk-UA')`: ціни з двома знаками, обсяги з одним. Роздільник тисяч у `uk-UA`
— нерозривний пробіл (U+00A0), тож тести порівнюють після нормалізації пробілів. `null` →
«—».

### Тема industrial

Одне джерело палітри — `src/theme.ts`:

```ts
export const palette = {
  navy900: '#0b1f3a',  // шапка, основні кнопки, головна серія графіка
  navy700: '#13315c',  // hover, друга серія
  navy400: '#5a7ba6',  // допоміжні серії (мін/макс), стовпці обсягу
  white:   '#ffffff',
  gray50:  '#f4f6f8',  // фон сторінки
  gray300: '#cfd6de',  // рамки, сітка графіка
  gray600: '#5b6675',  // другорядний текст, підписи осей
  gray900: '#1f2733',  // основний текст
}
```

`index.css` визначає ті самі значення як CSS-змінні. Тест стверджує, що змінні в CSS
збігаються з `palette`, тож два місця не можуть розійтися. Графік бере кольори з `palette`
напряму.

Стиль: прямі кути (2px), рамки товщиною 1px, без тіней і градієнтів, системний шрифт, таблиця з
тонкими горизонтальними лініями й зеброю на `gray50`. Помилки — текст + `role="alert"` + ліва
рамка `navy900`, без червоного: у палітрі користувача його немає.

Контраст перевіряє тест за формулою відносної яскравості WCAG: `gray900`/`gray50` і
`navy900`/`white` ≥ 7:1, `gray600`/`white` ≥ 4.5:1.

## Risks / Trade-offs

- **Перетворення часу — найкрихкіше місце** → воно зосереджене в одній чистій функції з
  тестами на обидва дні переходу і на два пояси браузера.
- **Категорійна вісь не показує проміжків у часі** → у джерелі проміжків немає. Якщо колись
  з'являться (пропущена доба), графік зімкне їх, а таблиця покаже правду.
- **`lttb` на рік погодинно може сховати короткий пік** → це стосується лише рендеру; tooltip і
  таблиця показують точні значення. Мінімальне й максимальне значення подобових даних
  зберігаються окремими серіями.
- **«< 1 с» залежить від машини користувача** → вимірюємо в реальному браузері й фіксуємо
  результат у звіті. Бюджет API — 46–62 мс, решта припадає на рендер.
- **Пресет «Рік» = 366 діб на межі ліміту** → свідомо: `завтра − 365 … завтра` включно дає рівно
  366 діб. Тест стверджує, що цей пресет лишається погодинним.
