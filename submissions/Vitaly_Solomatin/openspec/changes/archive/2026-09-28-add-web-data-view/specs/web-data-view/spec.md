## Purpose

Перегляд цін і обсягів торгів РДН у вебзастосунку: вибір діапазону дат і роздільності, графік
і таблиця з часом за Києвом, і такі стани завантаження, порожнього результату та помилок, які
користувач не сплутає між собою.

## ADDED Requirements

### Requirement: Вибір діапазону і роздільності

Застосунок SHALL дозволяти вибрати діапазон дат постачання пресетом («7 днів», «30 днів»,
«Рік», «Уся історія») або двома полями дат, а також роздільність «Погодинно» чи «Подобово». За
замовчуванням MUST показуватися погодинна роздільність за 7 діб, що закінчуються завтрашньою
добою постачання за Europe/Kyiv. Для діапазону понад 366 діб погодинна роздільність MUST бути
недоступною з поясненням, і застосунок MUST NOT надсилати такий запит до API. Діапазон, у якому
початкова дата пізніша за кінцеву, MUST NOT надсилатися до API.

#### Scenario: Типовий вигляд

- **GIVEN** сьогодні 28 вересня 2026 року за Києвом
- **WHEN** користувач відкриває застосунок
- **THEN** вибрано погодинну роздільність і діапазон з 23 по 29 вересня 2026 року

#### Scenario: Пресет «Уся історія»

- **GIVEN** користувач на погодинній роздільності
- **WHEN** він вибирає пресет «Уся історія»
- **THEN** діапазон починається 1 липня 2019 року
- **AND** роздільність перемикається на подобову, бо діапазон довший за 366 діб

#### Scenario: Погодинна роздільність для задовгого діапазону

- **GIVEN** вибрано діапазон довжиною 367 діб
- **WHEN** користувач намагається вибрати погодинну роздільність
- **THEN** погодинна роздільність недоступна
- **AND** показано пояснення, що погодинно можна переглянути не більше 366 діб
- **AND** запит до API з погодинною роздільністю не надсилається

#### Scenario: Перевернутий діапазон

- **GIVEN** користувач ввів початкову дату, пізнішу за кінцеву
- **WHEN** застосунок перевіряє діапазон
- **THEN** показано повідомлення про некоректний діапазон
- **AND** запит до API не надсилається

#### Scenario: Застаріла відповідь

- **GIVEN** користувач швидко змінив діапазон двічі поспіль
- **WHEN** відповідь на перший запит приходить пізніше за відповідь на другий
- **THEN** показуються дані другого запиту

### Requirement: Графік цін і обсягів

Застосунок SHALL показувати графік вибраних даних. Для погодинних даних графік MUST містити
ціну і обсяг продажу за кожен період. Для подобових MUST містити зважену за обсягом середню
ціну, мінімальну і максимальну ціну та сумарний обсяг продажу. Підписи часу на погодинному
графіку MUST бути за Europe/Kyiv незалежно від часового поясу браузера. Кольори серій MUST
належати палітрі теми застосунку.

#### Scenario: Погодинний графік

- **GIVEN** API повернуло погодинні дані за одну добу з 24 періодами
- **WHEN** застосунок будує графік
- **THEN** графік містить 24 точки ціни і 24 значення обсягу продажу

#### Scenario: Подобовий графік

- **GIVEN** API повернуло подобові дані
- **WHEN** застосунок будує графік
- **THEN** графік містить серії зваженої середньої, мінімальної і максимальної ціни та сумарного
  обсягу продажу

#### Scenario: Доба без зваженої ціни

- **GIVEN** у подобових даних для однієї доби зважена середня ціна порожня
- **WHEN** застосунок будує графік
- **THEN** для цієї доби на лінії зваженої ціни є розрив, а не нуль

#### Scenario: Час у браузері з іншим часовим поясом

- **GIVEN** браузер налаштовано на часовий пояс UTC
- **WHEN** графік показує період 13 доби 28 вересня 2026 року
- **THEN** підпис часу дорівнює 12:00 за Києвом

### Requirement: Час періоду за Києвом

Застосунок SHALL перетворювати дату постачання і номер періоду на час початку періоду за
Europe/Kyiv, відраховуючи період від опівночі доби постачання за Києвом у реальних годинах.
Перетворення MUST бути коректним для діб на 23 і 25 періодів. Коли у добу на 25 періодів
година повторюється, застосунок MUST показувати номер періоду поряд із часом.

#### Scenario: Звичайна доба

- **GIVEN** доба 28 вересня 2026 року
- **WHEN** перетворюється період 1
- **THEN** час початку дорівнює 00:00 за Києвом

#### Scenario: Доба переходу на літній час

- **GIVEN** доба 30 березня 2025 року на 23 періоди
- **WHEN** перетворюються періоди 3 і 4
- **THEN** час початку дорівнює 02:00 і 04:00 за Києвом відповідно

#### Scenario: Доба переходу на зимовий час

- **GIVEN** доба 26 жовтня 2025 року на 25 періодів
- **WHEN** перетворюються періоди 4 і 5
- **THEN** обидва мають час початку 03:00 за Києвом
- **AND** їх розрізняє номер періоду

### Requirement: Таблиця даних

Застосунок SHALL показувати ті самі дані, що й графік, таблицею в хронологічному порядку.
Погодинна таблиця MUST містити дату, період, час за Києвом, ціну і чотири обсяги. Подобова
таблиця MUST містити дату, мінімальну і максимальну ціну, просту та зважену середню, чотири
обсяги і кількість періодів. Таблиця SHALL ділитися на сторінки по 100 рядків. Числа MUST
форматуватися за `uk-UA`, а порожнє значення MUST показуватися як «—», а не як 0.

#### Scenario: Погодинна таблиця

- **GIVEN** API повернуло погодинні дані за одну добу
- **WHEN** застосунок показує таблицю
- **THEN** у ній 24 рядки з датою, періодом, часом, ціною і чотирма обсягами

#### Scenario: Посторінковий перегляд

- **GIVEN** API повернуло 8 760 погодинних рядків
- **WHEN** застосунок показує таблицю
- **THEN** на сторінці показано 100 рядків
- **AND** доступний перехід між 88 сторінками

#### Scenario: Формат чисел

- **GIVEN** ціна 14947.8 і обсяг 3246.2
- **WHEN** таблиця показує ці значення
- **THEN** вони відображаються як «14 947,80» і «3 246,2»

#### Scenario: Порожня зважена ціна

- **GIVEN** у подобових даних зважена середня ціна для доби порожня
- **WHEN** таблиця показує цю добу
- **THEN** у клітинці зваженої ціни стоїть «—»

### Requirement: Стани даних

Застосунок SHALL показувати стан завантаження, поки дані запитуються; стан «даних немає», коли
API повернуло порожній результат; стан «backend недоступний» на мережеву помилку чи помилку
сервера; і повідомлення API на помилку валідації. Порожній результат MUST NOT показуватися як
помилка, а помилка MUST NOT показуватися як порожній результат.

#### Scenario: Діапазон без даних

- **GIVEN** за вибраний діапазон у БД немає даних
- **WHEN** застосунок отримує відповідь
- **THEN** показано повідомлення «за цей період даних немає»
- **AND** графік і таблиця не показують помилки

#### Scenario: Backend недоступний під час запиту даних

- **GIVEN** backend не відповідає
- **WHEN** застосунок запитує дані
- **THEN** показано стан «backend недоступний» замість графіка й таблиці

#### Scenario: Помилка валідації від API

- **GIVEN** API відповідає 422 з повідомленням
- **WHEN** застосунок обробляє відповідь
- **THEN** показано повідомлення API

### Requirement: Час відображення історії

Від вибору діапазону до відмальованого графіка SHALL минати не більше однієї секунди для будь-
якого діапазону, доступного в UI: усієї історії подобово і до 366 діб погодинно.

#### Scenario: Уся історія подобово

- **GIVEN** у БД уся історія з 1 липня 2019 року
- **WHEN** користувач вибирає пресет «Уся історія»
- **THEN** графік відмальовано менш ніж за 1 с

#### Scenario: Рік погодинно

- **GIVEN** у БД уся історія
- **WHEN** користувач вибирає пресет «Рік» з погодинною роздільністю
- **THEN** графік відмальовано менш ніж за 1 с
