## MODIFIED Requirements

### Requirement: Стан з'єднання з API

Застосунок SHALL при завантаженні перевіряти живість backend і читати стан системи, а потім
показувати панель з'єднання в одному з трьох станів: завантаження; з'єднання в порядку, з
часом останньої перевірки й останнього оновлення даних; backend недоступний. Відповідь, що не
відповідає контракту, MUST показуватися як помилка з'єднання. Часи MUST відображатися за
часовим поясом Europe/Kyiv. Відсутність запусків у журналі MUST відображатися як «ще не було»,
а не як помилка. Застосунок MUST NOT запитувати облікові дані чи надсилати їх.

#### Scenario: З'єднання в порядку

- **GIVEN** backend доступний, і в журналі є запуски
- **WHEN** застосунок завантажився
- **THEN** панель показує, що з'єднання в порядку
- **AND** показує час останньої перевірки й останнього оновлення даних за Europe/Kyiv

#### Scenario: Час за київським часом

- **GIVEN** останній запуск почався о `2026-09-28T09:00:00Z`
- **WHEN** панель показує час останньої перевірки
- **THEN** показаний час дорівнює 12:00 28.09.2026

#### Scenario: Журнал порожній

- **GIVEN** backend доступний, і запусків ще не було
- **WHEN** застосунок завантажився
- **THEN** панель показує, що з'єднання в порядку
- **AND** на місці часу перевірки й оновлення показує «ще не було»

#### Scenario: Backend недоступний

- **GIVEN** backend не відповідає або відповідає помилкою сервера
- **WHEN** застосунок завантажився
- **THEN** панель показує стан «backend недоступний»

#### Scenario: Неочікувана відповідь

- **GIVEN** backend відповідає кодом 200, але тіло не відповідає контракту стану системи
- **WHEN** застосунок обробляє відповідь
- **THEN** панель показує стан помилки з'єднання, а не порожні значення

#### Scenario: Облікові дані не надсилаються

- **GIVEN** застосунок завантажено
- **WHEN** він звертається до API
- **THEN** запити не містять заголовка `Authorization`
- **AND** застосунок не показує жодної форми чи вікна входу

## REMOVED Requirements

### Requirement: Автентифікація засобами браузера

**Reason**: Автентифікацію API прибрано повністю (зміна `remove-auth`, вимога `http-api`
«Доступ лише з localhost»). Застосунку більше нема чого запитувати, тому системне вікно
браузера, стан «потрібна автентифікація» і посилання «Увійти» зникають. Повноцінна
session-based автентифікація з власною сторінкою входу — окрема майбутня зміна.

**Migration**: Дій не потрібно. Облікові дані, закешовані браузером після системного вікна,
лишаються в кеші браузера, але API їх ігнорує і вони нічого не змінюють.
