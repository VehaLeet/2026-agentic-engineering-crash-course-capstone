## Purpose

Мережевий інтерфейс сервісу моніторингу РДН: запустити збір ззовні без очікування на джерело,
простежити результат запуску і прочитати стан системи — усе лише для автентифікованого
користувача, з кредами, що існують тільки в оточенні процесу.

## ADDED Requirements

### Requirement: Автентифікація Basic Auth

Усі ендпойнти, крім перевірки живості, SHALL вимагати HTTP Basic Auth. Очікувані логін і пароль
MUST братися виключно з оточення процесу. Запит без облікових даних або з хибними MUST
відхилятися з кодом 401 і заголовком, що запрошує Basic-автентифікацію, і MUST NOT виконувати
жодної дії. Порівняння облікових даних MUST виконуватись за сталий час.

Застосунок MUST NOT стартувати, якщо логін або пароль не задані в оточенні.

#### Scenario: Запит без облікових даних

- **GIVEN** застосунок запущено з логіном і паролем в оточенні
- **WHEN** надходить `GET /status` без заголовка автентифікації
- **THEN** відповідь має код 401
- **AND** містить заголовок `WWW-Authenticate` зі схемою Basic

#### Scenario: Хибний пароль

- **GIVEN** застосунок запущено з логіном і паролем в оточенні
- **WHEN** надходить `POST /collect` з правильним логіном і хибним паролем
- **THEN** відповідь має код 401
- **AND** жодного запуску збору не створено

#### Scenario: Правильні облікові дані

- **GIVEN** застосунок запущено з логіном і паролем в оточенні
- **WHEN** надходить `GET /status` з цими обліковими даними
- **THEN** відповідь має код 200

#### Scenario: Облікові дані не задані

- **GIVEN** в оточенні немає логіна або пароля
- **WHEN** застосунок запускається
- **THEN** запуск завершується помилкою конфігурації
- **AND** застосунок не приймає запитів

### Requirement: Асинхронний ручний запуск збору

`POST /collect` SHALL створювати запис запуску зі способом `manual`, запускати збір у фоні й
відповідати кодом 202 з ідентифікатором запуску та шляхом до його стану, не чекаючи на
завершення збору. Опорною датою збору MUST бути поточна дата за часовим поясом Europe/Kyiv.

Збій фонового збору MUST NOT впливати на роботу застосунку і MUST бути видимим у стані запуску.

#### Scenario: Запуск збору

- **GIVEN** автентифікований користувач
- **WHEN** він надсилає `POST /collect`
- **THEN** відповідь має код 202 і містить ідентифікатор запуску та шлях `/runs/{id}`
- **AND** відповідь приходить без очікування на завантаження з джерела

#### Scenario: Запуск завершується успішно

- **GIVEN** збір запущено через `POST /collect`, і джерело має нові дані
- **WHEN** фоновий збір завершився
- **THEN** `GET /runs/{id}` повертає статус `success` і перелік змінених діб постачання
- **AND** спосіб запуску цього запису — `manual`

#### Scenario: Збій джерела у фоновому зборі

- **GIVEN** збір запущено через `POST /collect`, а джерело недоступне
- **WHEN** фоновий збір завершився
- **THEN** `GET /runs/{id}` повертає статус `error` і текст помилки
- **AND** застосунок продовжує відповідати на запити

#### Scenario: Два запуски одночасно

- **GIVEN** один збір, запущений через `POST /collect`, ще триває
- **WHEN** надходить другий `POST /collect`
- **THEN** обидва запити отримують 202 з різними ідентифікаторами
- **AND** другий запуск завершується статусом `skipped_locked`

#### Scenario: Опорна дата за київським часом

- **GIVEN** годинник сервера в UTC показує 30 вересня 22:30, тобто в Києві вже 1 жовтня
- **WHEN** надходить `POST /collect`
- **THEN** опорною датою збору є 1 жовтня

### Requirement: Стан окремого запуску

`GET /runs/{id}` SHALL повертати стан запуску: час початку і завершення, статус, спосіб запуску,
перелік змінених діб постачання і текст помилки. Поки запуск триває, статус і час завершення
MUST бути порожніми. Для невідомого ідентифікатора MUST повертатись код 404.

#### Scenario: Запуск ще триває

- **GIVEN** збір запущено, і він ще не завершився
- **WHEN** запитується `GET /runs/{id}`
- **THEN** відповідь має код 200
- **AND** статус і час завершення порожні

#### Scenario: Невідомий запуск

- **GIVEN** запуску з ідентифікатором 999999 не існує
- **WHEN** запитується `GET /runs/999999`
- **THEN** відповідь має код 404

#### Scenario: Некоректний ідентифікатор

- **GIVEN** автентифікований користувач
- **WHEN** запитується `GET /runs/abc`
- **THEN** відповідь має код 422

### Requirement: Стан системи

`GET /status` SHALL повертати останній запуск будь-якого статусу, останній запуск, що змінив
дані, і останні запуски зі статусом `error`, найновіші першими. Порожній журнал MUST повертати
порожні значення без помилки.

#### Scenario: Стан після кількох запусків

- **GIVEN** журнал містить запуск `success`, після нього запуск `no_changes`
- **WHEN** запитується `GET /status`
- **THEN** останнім запуском є запуск `no_changes`
- **AND** останнім оновленням даних є запуск `success`

#### Scenario: Порожній журнал

- **GIVEN** жодного запуску ще не було
- **WHEN** запитується `GET /status`
- **THEN** відповідь має код 200
- **AND** останній запуск і останнє оновлення порожні, перелік помилок порожній

### Requirement: Перевірка живості

`GET /health` SHALL відповідати кодом 200 без автентифікації і MUST NOT розкривати жодних даних
про запуски, дані РДН чи конфігурацію.

#### Scenario: Перевірка живості без облікових даних

- **GIVEN** застосунок запущено
- **WHEN** надходить `GET /health` без заголовка автентифікації
- **THEN** відповідь має код 200
- **AND** тіло відповіді не містить даних про запуски чи конфігурацію
